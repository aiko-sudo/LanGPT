# LanGPT V1.3.6 定向问题审计

审计对象：当前私有开发树及已安装 V1.3.6；范围为额度显示、SSH/内置 Tailscale、打包与源码可追溯性，不代表全功能安全审计。

## 已确认问题

1. 用量缓存混淆：`UsageLimits.updateStats` 在 `fetchedAt == 0` 时更新同一个时间戳；`fresh()` 不检查额度窗口或额度读取失败；`MainActivity.usageInfo(false)` 只依据 fresh 决定是否自动重读。真实 UsageLimits JVM 测试执行统计成功→额度请求失败，输出 `QUOTA_FAILED=true, CACHE_SAYS_FRESH=true`，再次打开可不自动重试；手动刷新仍可强制请求。不能据此推断当前用户实际仍有上游报错。
2. 内置连接取消不立即中断待建立拨号：`TsnetSocketFactory.close()` 只在 Dial 已返回后拿得到 socket；Go `Dial` 固定 20 秒 deadline。生产 SocketFactory 加可控阻塞 Dial 桩的 JVM 测试输出 `CANCELLED_DIAL_STILL_BLOCKED=true`, `CLEANS_UP_AFTER_DIAL_RETURNS=true`。已连接数据流的关闭不在此结论范围。
3. 无备用地址时直连最长等待 20 秒：`SshTransport.java:174` 为 fallback 为空选择 20000ms，随后才拨内置节点；配置相同备用地址可走 3000ms 逻辑，但不应要求用户重复配置。实际耗时还取决于网络是立即拒绝还是超时。
4. 内置节点无显式停用：`TsnetSetup` 会设置 enabled=true 并自动启动，显示的“关闭”只关闭对话框；当前代码没有 stop/清除 enabled 的 UI。节点不会因关闭该对话框而停止。
5. 交付覆盖：V1.3.6 APK badging `native-code: arm64-v8a`，其他 ABI 设备的兼容性未覆盖。用户当前手机已安装运行。
6. 源码可追溯性：私有开发树 HEAD 为 V1.3.3，新代码、AAR 及版本更新未全部纳入 Git；Go 生成源位于独立的 langpt-tsnet-proto/go 中。不能以现有 Git HEAD 构建已交付的 V1.3.6。未经授权不得推公开仓库。

## 待验证风险
- MainActivity 异步启动内置节点并同时触发连接，冷启动可能出现先拨号后 node ready 的竞态；代码路径成立，尚未在真机强制复现。
- Wi-Fi/蜂窝切换、后台保活、进程回收、隧道连续文件传输、弱网与多个 Android 设备尚未完成系统性验收，不能称已失败。
- 本机未以真实上游请求重新确认剩余额度当前是否可用；额度失败的上游网络问题与上述客户端缓存错误相互独立。

## 已通过证据
- 用户在手机确认 V1.3.6 连接速度快；NAS 实际 status 显示正式 langpt-android 节点 IPv6 direct；SSH 实测 RTT 约 32–52ms。
- V1.3.6 `assembleDebug` 成功，package versionCode 91，4 项定向测试通过；随后完整运行 35 个 Python 测试文件，退出码均为 0。该数字是测试文件，不等于具体测试用例数或真机全功能验证。
- JVM 额度测试和取消测试为隔离、可控本地测试，不修改手机连接或生产数据。
