# LanGPT 轻量实用功能路线图（对照 V1.1.6）

状态：仅调研和方案，不修改业务代码、不发布新版。原则：轻量、好用、高效、人性化；不重复建设，不堆顶栏菜单，不新增常驻服务，不调用额外付费模型来包装已有输出。

## 一、已有能力与缺口

本地代码证据：
- WorkPanel.java：多会话按项目汇总、状态/时长/最新活动、过程折叠、点击切换；目前用插入顺序分组，状态把“空闲/已结束”合并，没有可见的未读结果与注意力排序实现。
- LiveStatusNotifications.java：按会话运行/审批通知，completeSnapshot 已截取最终回复。因此“再做完成通知”是重复建设；可以增强结果导航和未读状态。
- TurnController.java：已有 pendingMessages Map、queueMessage、cancelQueuedMessage、sendQueuedMessage，但每个 profile/thread 当前只存一个 PendingMessage；多条队列是增强，不是从零新增排队。
- RemoteApp.java：已有 turn/diff/updated，将 diff 放进 fileChange ChatItem。缺的是手机友好的结果/文件审阅整合，不能宣称 diff 协议缺失。
- ConversationState.java：已有按会话的 draft、附件等内存状态；跨进程草稿恢复不等同于 Activity 保存状态，需要另做加密持久化与验收。
- SftpBrowser.java / RemoteFiles.java：只读目录/文件元数据、排序、下拉刷新、后台单次预取已具备；普通文件目前点击显示属性而非文本预览或上下文引用。

## 二、外部来源与证据层级

- Superset 的 README 描述侧栏工作状态/完成提醒、终端预设、Git worktree，以及任务间独立工作区；明确 worktree 不等于进程沙箱，也不能阻止合并冲突。本轮是 README 级核验，未安装运行。[10]
- LinkShell 的 README 描述手机端消息队列可重排、撤回或送入当前回合。本轮仅把其交互作为参考，未声称所有 Runtime 都支持同样语义。[11]
- HAPI 的分页/发送协议区分排队、已消费、送达未知，并明确送达未知不能自动重试。它还建议会话级缓存和轻量尾部同步；不能把 HAPI 的具体页大小直接当成本项目的性能目标。[12]
- HAPI messages.ts 中 mergeMessages 的实际源码按 id/localId 合并乐观消息与服务端回显，保留已消费时间，不让旧 queued 状态覆盖已消费状态。已读源码，未运行 HAPI。[13]
- Superset 的 Diff Viewer 文档描述逐文件聚焦、查看差异，以及携带文件/行范围向 Agent 发送反馈。本项目只借鉴“看清改动再提反馈”，不搬入完整 Git 提交/PR 工作台。[14]

## 三、推荐功能：来源机制→本地差距→最小动作→入口→验收

| 优先级 | 功能 | 最小实现/交互 | 入口 | 验收门 | 成本判断 |
|---|---|---|---|---|---|
| 第一批 | 注意力收件箱 | 复用现有任务面板，增加“待处理/运行中/已结束”筛选；待审批、失败、已完成未读优先；普通历史同步不能伪装成运行任务。未读以 thread+turn+结果版本判定，不按每个 token 计数 | 工作面板顶部轻量筛选，不增加首页菜单 | A/B 并行：B 待审批时优先；A 完成只出现一次未读；看过结果后清标；重放不重复提醒；断连显示未知 | 低，不需要新协议或后台轮询 |
| 第一批 | 任务结果卡 | 复用最终回复、diff、错误、工具执行结果，确定性展示“结果摘要/改动文件/已观察到的检查/产物路径”；不能把 turn/completed 等同于用户目标验收通过；文件路径仅用实际输出 | 已结束任务卡，点击看详情 | 进程退出/任务回合结束/测试退出码分别标注；无测试记录就写“未验证”；多回合不混结果；没有实际产物就不生成假入口 | 低到中，不额外调用模型总结 |
| 第一批 | SFTP 文件预览与引用 | 小文本按需读取；图片复用现有预览；“引用到当前任务”默认仅插入规范路径，读取内容或发给模型须明确确认。保留只读，不做手机代码编辑器 | 文件点击后的预览页及一个引用操作 | UTF-8/非文本/大文件都有明确反馈；限制字节数并标截断；符号链接解析后重查范围；打开文件不自动发任务；引用不串会话 | 中，需新增有边界的读文件操作 |
| 第二批 | 项目快捷任务与可靠草稿 | 把常用指令保存为项目模板，点击仅填入草稿；模板不暗改 Runtime/模型/权限；当前已有草稿先提示。草稿按连接+会话加密保存 | 输入框已有附件/更多入口或项目空态，不增加主菜单项 | 误触不启动任务；A/B 草稿隔离；杀进程再进可恢复；连接密码不能被写入模板 | 低到中，无新增服务 |
| 第二批 | 多条待办消息 | 从现有单条 PendingMessage 扩展为有上限列表，可编辑/删除/排序；默认不串行自动执行。确需自动接下一条，用户显式启用且失败/待审批即暂停 | 输入框上方待发条 | 队列顺序准确；取消已消费项不得假装成功；断网、送达未知不自动重发；不支持的 Runtime 隐藏“插入当前回合” | 中到高，需持久化与协议对账，不是单纯画列表 |
| 条件增强 | 同目录并行提醒 | 启动第二个同工作目录写任务时提示“可能改同一批文件”，默认建议独立目录；提示是风险告知，不声称已发生冲突。允许用户确认继续，不静默更改 cwd | 发送前轻量提示 | 不同目录不乱报；阅读任务可忽略；重复提示不扰人；不自动 stash/reset/删除文件 | 低；真正 worktree 隔离仅在明确需求时开启 |

前三项组成最小闭环：找到需要处理的任务→看懂结果→查看相关文件并给下一步指令。无需新增一级页面体系，复用工作面板和 SFTP。

## 四、先过可靠性门禁，再扩展高级排队

这不是“新增卖点”，而是扩展多任务前必须复核的底座：
- A/B 同时运行、网络切换、重复事件、历史补回后，结果与审批不串任务。
- 冷启动先显示本地可用状态；后台同步不能抢前台导航或冒充执行中。
- 收到服务端确认与真正被原生 CLI 消费是不同状态；未知送达禁止自动重发带副作用任务。来源 HAPI 的机制只能作设计参考，必须由本地桥接层兑现。[12][13]
- 以固定事件 fixture 和真实独立 CLI/SFTP 测试分层验收；手机视觉/手势只能由设备测试确认，不能被编译通过替代。

本轮仅记录这些门禁，不擅自执行生产测试或修改业务代码。

## 五、明确不做

- 不再增加一套通知、终端、项目管理或工作面板。
- 不做全功能远程桌面、内嵌 IDE、大量插件中心、额外中继服务/账号体系。
- 不为了生成漂亮的结果摘要增加收费模型调用；先复用真实输出。
- 不做全局“自动批准”、断线无限重试、送达未知自动重发。
- 不默认引入 worktree/自动合并/自动清理；多会话并发不是写入隔离。

## 六、建议顺序

先做注意力收件箱与结果卡；SFTP 文件预览/路径引用作为下一小批。模板、持久草稿再后置；多条自动队列和 worktree 等有明确需求、可靠性门禁通过后才加。
